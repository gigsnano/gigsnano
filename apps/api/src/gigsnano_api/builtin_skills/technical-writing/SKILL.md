# Technical Writing

**Use when:** a work item produces or updates docs (README, API reference,
runbook, guide).
**Not for:** code changes with no documentation deliverable.

## Steps
1. Lead with the reader's task: what they can do after reading, in the first
   sentence. No throat-clearing.
2. Prefer short sentences, concrete examples, and runnable commands over prose.
3. Structure for scanning: headings, short paragraphs, lists for steps.
4. State prerequisites and the expected result of each step.
5. Verify every command/code sample actually runs — never document what you
   haven't confirmed.

## Negative signal
If a paragraph doesn't help the reader do the task, cut it.
